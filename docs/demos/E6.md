# Epic E6 Demo Walkthrough — Search & Investigation Memory

This document provides a complete, verifiable step-by-step walkthrough of the **Casefile Search Engine & 4-Tier Investigation Memory**, covering exact phrase search, fuzzy OCR matching (`AC-SRCH-02`), alias expansion (`AC-SRCH-04`), multi-signal composite ranking & transparent explanations (`AC-SRCH-05`), search reproducibility (`AC-SRCH-06`), coverage reporting (`AC-SRCH-03`), saved searches, search monitors, relevance feedback, 4-tier memory state inspection ("What Casefile Knows"), deterministic Context Manifest assembly with 200k token budgeting & omission tracking, and strict Invariant I10 permission pre-filtering (`AC-SRCH-01`).

---

## 1. Overview of Demonstrated Capabilities

1. **AC-SRCH-01 & Invariant I10 — Permission Pre-Filtering**: Restricted and withdrawn sources are filtered out before scoring and never revealed in search hits, facets, or coverage reports.
2. **AC-SRCH-02 — Fuzzy Matching**: Levenshtein-based fuzzy matching successfully matches OCR-degraded tokens (e.g. `Merldían Tradlng Ltd` matches `Meridian Trading~`).
3. **AC-SRCH-03 — Retrieval Coverage Reporting**: Every search response includes a transparent coverage report with total chunks indexed, indexed sources, unindexed sources count, and status breakdown.
4. **AC-SRCH-04 — Entity Alias Expansion**: Searches prefixed with `entity:<name>` expand across the canonical entity name and all historical/prior aliases, explicitly reporting which alias matched.
5. **AC-SRCH-05 — Transparent Explanation**: Search result items feature detailed explanation breakdowns showing retrieval path, matched terms, and composite scoring contributions.
6. **AC-SRCH-06 — Search Reproducibility**: Re-executing queries against pinned index generations and weights versions returns identical ordering and scores.
7. **Saved Searches, Monitors & Feedback (SRCH-13, 14, 18)**: Saving named queries, setting automated intake monitors, and submitting relevance feedback for re-ranking.
8. **4-Tier Investigation Memory (PRD §13 & §20 / MEM-01..08)**: Inspecting Definition Memory (Tier 1), State Memory (Tier 2), Working Memory (Tier 3), and assembling deterministic Context Manifests with 200k token limits and auditable `OmissionRecords`.

## 3. Step-by-Step Walkthrough

### Step 1: Register Organization & Create Investigation with Scope

```powershell
# 1. Register investigator account
$reg = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/auth/register" -ContentType "application/json" -Body (@{
    email = "lead-investigator@casefile-intel.example"
    password = "MasterPassword123!"
    name = "Elena Rostova"
    orgName = "Alpha Capital Intelligence"
} | ConvertTo-Json)

$TOKEN = $reg.accessToken
$HEADERS = @{ Authorization = "Bearer $TOKEN" }

# 2. Get default workspace
$workspaces = Invoke-RestMethod -Method Get -Uri "$API_URL/v1/workspaces" -Headers $HEADERS
$WORKSPACE_ID = $workspaces.items[0].id

# 3. Create Investigation with Tier 1 Scope & Spine Questions
$inv = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations" -Headers $HEADERS -ContentType "application/json" -Body (@{
    workspace_id = $WORKSPACE_ID
    name = "Operation Meridian Audit"
    objective = "Investigate suspicious offshore disbursements and beneficial ownership"
    sensitivity = "internal"
    scope = @{
        subjects = @(
            @{ descriptor = "Meridian Trading Group"; subject_type = "organization"; role = "primary_subject" }
        )
    }
} | ConvertTo-Json -Depth 5)

$INV_ID = $inv.id
Write-Host "Created Investigation ID: $INV_ID"
```

---

### Step 2: Ingest Reference Documents & Entities

```powershell
# 1. Ingest clean document
$doc1 = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/sources" -Headers $HEADERS -ContentType "application/json" -Body (@{
    filename = "Meridian_Loan_Agreement_2023.txt"
    mime_type = "text/plain"
    source_class = "primary_record"
    raw_text = "Meridian Trading Group executed a loan agreement of 500,000 USD on 2023-01-10 with Apex Holdings."
    acquisition_record = @{ origin = "Bank Vault"; custodian = "Compliance Officer"; acquisition_method = "upload" }
} | ConvertTo-Json)

# 2. Ingest OCR-degraded document
$doc2 = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/sources" -Headers $HEADERS -ContentType "application/json" -Body (@{
    filename = "Scanned_Corporate_Filing_1998.txt"
    mime_type = "text/plain"
    source_class = "primary_record"
    raw_text = "Merldían Tradlng Ltd was formerly incorporated as Kestrel Nominees Ltd in Panama."
    acquisition_record = @{ origin = "Panama Registry OCR"; custodian = "Archivist"; acquisition_method = "upload" }
} | ConvertTo-Json)

# 3. Register Entity with Former Name Alias (AC-SRCH-04)
$entity = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/entities" -Headers $HEADERS -ContentType "application/json" -Body (@{
    type = "Organization"
    canonical_name = "Vantor Holdings Ltd"
    is_focal = $true
    aliases = @(
        @{ value = "Kestrel Nominees Ltd"; alias_type = "former_name"; confidence = 0.95 }
    )
} | ConvertTo-Json -Depth 5)

Write-Host "Admitted Documents and Entity: $($entity.canonical_name)"
```

---

### Step 3: Exact Phrase Search & Transparent Explanation (SRCH-01, AC-SRCH-05)

```powershell
# Execute exact phrase search
$exactSearch = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/search" -Headers $HEADERS -ContentType "application/json" -Body (@{
    query = '"loan agreement"'
    mode = "exact"
} | ConvertTo-Json)

Write-Host "Exact Search Total Hits: $($exactSearch.total_hits)"
Write-Host "Matched Snippet: $($exactSearch.items[0].snippet)"
Write-Host "Explanation Contributing Signals:"
$exactSearch.items[0].explanation.contributing_signals | Format-Table
```

---

### Step 4: Fuzzy OCR Matching (AC-SRCH-02)

```powershell
# Search using fuzzy token modifier
$fuzzySearch = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/search" -Headers $HEADERS -ContentType "application/json" -Body (@{
    query = "Meridian Trading~"
    mode = "keyword"
} | ConvertTo-Json)

Write-Host "Fuzzy Match Hit Count: $($fuzzySearch.total_hits)"
Write-Host "Matched Filename: $($fuzzySearch.items[0].source_filename)"
Write-Host "Matched Terms: $($fuzzySearch.items[0].explanation.matched_terms -join ', ')"
```

---

### Step 5: Entity Alias Expansion (AC-SRCH-04)

```powershell
# Search by entity canonical name with automatic alias resolution
$entitySearch = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/search" -Headers $HEADERS -ContentType "application/json" -Body (@{
    query = "entity:Vantor Holdings Ltd"
    mode = "entity"
} | ConvertTo-Json)

Write-Host "Entity Search Hits: $($entitySearch.total_hits)"
Write-Host "Matched Document: $($entitySearch.items[0].source_filename)"
Write-Host "Matched Alias: $($entitySearch.items[0].explanation.matched_alias)"
```

### Step 7: Saved Searches, Monitors & Relevance Feedback (SRCH-13, 14, 18)

```powershell
# 1. Save Search Query
$saved = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/search/saved" -Headers $HEADERS -ContentType "application/json" -Body (@{
    name = "Key Loan Contracts"
    query = '"loan agreement"'
    search_mode = "exact"
} | ConvertTo-Json)
Write-Host "Created Saved Search ID: $($saved.id)"

# 2. Create Search Monitor
$monitor = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/search/monitors" -Headers $HEADERS -ContentType "application/json" -Body (@{
    saved_search_id = $saved.id
    name = "New Loan Agreement Alerts"
    query = '"loan agreement"'
} | ConvertTo-Json)
Write-Host "Created Monitor ID: $($monitor.id)"

# 3. Submit Relevance Feedback
$feedback = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/search/feedback" -Headers $HEADERS -ContentType "application/json" -Body (@{
    query = "loan agreement"
    source_id = $doc1.id
    is_relevant = $true
    notes = "Highly relevant loan terms"
} | ConvertTo-Json)
Write-Host "Feedback Acknowledged: $($feedback.message)"
```

### Step 8: Inspect 4-Tier Memory & Assemble Context Manifest (MEM-01..08)

```powershell
# 1. Inspect "What Casefile Knows" (Tiers 1, 2, 3)
$memory = Invoke-RestMethod -Method Get -Uri "$API_URL/v1/investigations/$INV_ID/memory" -Headers $HEADERS
Write-Host "Tier 1 Objective: $($memory.tier1.objective)"
Write-Host "Tier 2 Focal Entities: $($memory.tier2.focal_entities.canonical_name -join ', ')"
Write-Host "Tier 2 Corpus Profile: $($memory.tier2.corpus_profile.total_sources) sources, $($memory.tier2.corpus_profile.total_chunks) chunks"

# 2. Assemble Deterministic Context Manifest
$manifest = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/memory/manifest" -Headers $HEADERS -ContentType "application/json" -Body (@{
    operation = "synthesis"
    working_context = @{ current_view = "entity_dossier"; active_entity = $entity.id }
} | ConvertTo-Json -Depth 5)

Write-Host "Assembled Context Manifest ID: $($manifest.id)"
Write-Host "Total Allocated Tokens: $($manifest.token_budget.total_allocated) / 200,000 limit"
Write-Host "Omitted Items Count: $($manifest.omitted.Count)"
```
