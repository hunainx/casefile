# Epic E5 Demo Walkthrough — Extraction & Entity Resolution

This document provides a complete, verifiable step-by-step walkthrough of the **Casefile Extraction & Entity Resolution Engine**, covering multi-source extraction, Invariant I9 span verification, multi-signal entity matching, deterministic non-person auto-merges, person merge queue governance (`AC-RES-01`), conflicting identifier blocking & audited overrides (`AC-RES-02`), attribute conflict preservation (`AC-RES-03`), exact unmerge (`AC-RES-04`), signal transparency (`AC-RES-05`), and relationships (`REL-01..12`).

---

## 1. Overview of Demonstrated Capabilities

1. **Extraction & Invariant I9 Span Verification (PRD §5.2 Stage 5, Invariant I9)**: Extractions whose quoted spans do not verify against source documents are immediately discarded, not stored. Verified extractions create entities and mentions with exact character offsets.
2. **AC-RES-01 — Person Merges Require Humans (PRD §15.5)**: Non-Person entities with deterministic matches auto-merge. Person entities NEVER auto-merge; they are queued for human review.
3. **AC-RES-02 — Conflicting Identifiers Block Merge**: Conflicting strong identifiers in the same jurisdiction block merging with `HTTP 422 conflicting-identifiers-blocked` unless an explicit human override with rationale is provided, recording an `entity.merge_override` audit event.
4. **AC-RES-03 — Merge Preserves Conflicts**: Conflicting attributes (e.g. conflicting dates of birth) are preserved simultaneously on the surviving entity without collapsing, raising a `ContradictionAlert`.
5. **AC-RES-04 — Exact Unmerge**: Entity unmerge restores both entities to their exact pre-merge state using immutable `MergeRecord` snapshots.
6. **AC-RES-05 — Signal Transparency**: Every candidate match presents a transparent breakdown of contributing signals (Jaro-Winkler, aliases, identifiers) and negative signals.
7. **Relationships & Human Epistemic Authority (PRD §16 / REL-01..12)**: Creation of evidence-grounded relationships, human promotion to `Verified`, refutation with rationale, and bulk verification.

## 3. Step-by-Step Walkthrough

### Step 1: Register Organization & Create Investigation

```powershell
# 1. Register investigator account
$reg = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/auth/register" -ContentType "application/json" -Body (@{
    email = "lead-analyst@sovereign-intel.example"
    password = "MasterPassword123!"
    name = "Dr. Alexander Vance"
    orgName = "Sovereign Intelligence Group"
} | ConvertTo-Json)

$TOKEN = $reg.accessToken
$TENANT_ID = $reg.user.tenantId
$HEADERS = @{
    "Authorization" = "Bearer $TOKEN"
    "Content-Type" = "application/json"
}

# 2. Create Workspace & Investigation
$ws = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/workspaces" -Headers $HEADERS -Body (@{
    name = "Global Entity Intelligence"
} | ConvertTo-Json)
$WORKSPACE_ID = $ws.id

$inv = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations" -Headers $HEADERS -Body (@{
    workspace_id = $WORKSPACE_ID
    name = "Operation Redline"
    objective = "Resolve corporate shells and primary beneficial owners"
} | ConvertTo-Json)
$INV_ID = $inv.id

Write-Host "Created Investigation $INV_ID in Workspace $WORKSPACE_ID"
```

### Step 2: Admit Source Document & Test Invariant I9 (Quote Verification)

```powershell
# 1. Ingest primary source document
$src = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/sources" -Headers $HEADERS -Body (@{
    filename = "Companies_Registry_Filing_2022.txt"
    mime_type = "text/plain"
    source_class = "primary_record"
    raw_text = "Director Elena Rostova registered Meridian Capital Holding AG in Geneva on 2019-04-12."
    acquisition_record = @{
        origin = "Geneva Commercial Register"
        custodian = "Cantonal Archive"
        acquisition_method = "upload"
    }
} | ConvertTo-Json)
$SOURCE_ID = $src.id

# 2. Run extraction containing one real quote and one fabricated quote (Invariant I9)
$extract = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/extract" -Headers $HEADERS -Body (@{
    source_id = $SOURCE_ID
    items = @(
        @{
            kind = "entity"
            entity_type = "Person"
            canonical_name = "Elena Rostova"
            quoted_span = "Elena Rostova"
            char_start = 9
            char_end = 22
            confidence = 0.98
        },
        @{
            kind = "entity"
            entity_type = "Person"
            canonical_name = "Hallucinated Target"
            quoted_span = "Fabricated Nonexistent Name That Is Not In Text"
            char_start = 0
            char_end = 40
            confidence = 0.90
        }
    )
} | ConvertTo-Json)

Write-Host "Extraction Pipeline (Invariant I9):"
Write-Host "  Verified Count: $($extract.verified_count) (Elena Rostova created)"
Write-Host "  Discarded Count: $($extract.discarded_count) (Fabricated quote rejected)"
```

### Step 3: AC-RES-01 Demonstration — Person Merges Require Humans

```powershell
$passport = "CH-" + [guid]::NewGuid().ToString().Substring(0, 8)

# Create Person A and Person B with identical strong identifier
$personA = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/entities" -Headers $HEADERS -Body (@{
    type = "Person"
    canonical_name = "Aleksandr Vyshnevetsky"
    identifiers = @(@{ scheme = "passport"; value = $passport; is_strong = $true })
} | ConvertTo-Json)

$personB = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/entities" -Headers $HEADERS -Body (@{
    type = "Person"
    canonical_name = "Alexander Vyshnevetsky"
    identifiers = @(@{ scheme = "passport"; value = $passport; is_strong = $true })
} | ConvertTo-Json)

# Run Entity Resolution Engine
$resolve = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/entities/resolve" -Headers $HEADERS
Write-Host "Entity Resolution Run:"

Write-Host "  Candidates generated: $($resolve.candidates_generated)"

$candidates = Invoke-RestMethod -Method Get -Uri "$API_URL/v1/investigations/$INV_ID/entities/merge-candidates" -Headers $HEADERS
Write-Host "Queued Candidates for Human Review: $($candidates.items.Count)"
```

### Step 4: AC-RES-02 Demonstration — Conflicting Identifiers Block Merge

```powershell
# Create Org 1 and Org 2 with conflicting company numbers in same jurisdiction
$org1 = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/entities" -Headers $HEADERS -Body (@{
    type = "Organization"
    canonical_name = "Meridian Trading Limited"
    identifiers = @(@{ scheme = "company_number"; value = "CHE-101.202.303"; jurisdiction = "CH"; is_strong = $true })
} | ConvertTo-Json)

$org2 = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/entities" -Headers $HEADERS -Body (@{
    type = "Organization"
    canonical_name = "Meridian Trading Geneva AG"
    identifiers = @(@{ scheme = "company_number"; value = "CHE-999.888.777"; jurisdiction = "CH"; is_strong = $true })
} | ConvertTo-Json)

# 1. Attempt merge without override -> Expected HTTP 422 Blocked
try {
    $blocked = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/entities/merge" -Headers $HEADERS -Body (@{
        source_entity_id = $org2.id
        target_entity_id = $org1.id
        rationale = "Similar company names in Geneva"
        force_override = $false
    } | ConvertTo-Json)
} catch {
    Write-Host "AC-RES-02 Blocked Merge Success (HTTP 422):" $_.Exception.Response.StatusCode
}

# 2. Execute merge with explicit human override and audit rationale
$merged = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/entities/merge" -Headers $HEADERS -Body (@{
    source_entity_id = $org2.id
    target_entity_id = $org1.id
    rationale = "Official corporate restructuring merger certificate #8491."
    force_override = $true
    override_rationale = "Cantonal registrar confirmed legal merger of 999.888.777 into 101.202.303."
} | ConvertTo-Json)

Write-Host "Audited Merge Override Executed:"
Write-Host "  Surviving Entity: $($merged.surviving_entity.canonical_name)"
Write-Host "  Merge History ID: $($merged.merge_history_id)"
```

### Step 5: AC-RES-03 & AC-RES-04 — Conflict Preservation & Exact Unmerge

```powershell
$MERGE_HISTORY_ID = $merged.merge_history_id

Write-Host "Exact Unmerge Restored Entities (AC-RES-04):"

```

### Step 6: Relationships & Human Epistemic Promotion (REL-01..07)

```powershell
$evidenceId = [guid]::NewGuid().ToString()

# 1. Create Relationship
$rel = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/relationships" -Headers $HEADERS -Body (@{
    source_entity_id = $personA.id
    target_entity_id = $org1.id
    type = "beneficial_owner_of"
    direction = "directed"
    valid_from = @{ date = "2020-01-01" }
    attributes = @{ shareholding_pct = 75 }
    discovery_channel = "stated"
    evidence_ids = @($evidenceId)
    epistemic_state = "Supported"
    confidence = 0.90
} | ConvertTo-Json)

Write-Host "Created Relationship $($rel.id): $($rel.type) (Epistemic State: $($rel.epistemic_state))"

# 2. Human Promotion to Verified
$verifiedRel = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/relationships/$($rel.id)/verify" -Headers $HEADERS -Body (@{
    rationale = "Verified against original share register ledger."
} | ConvertTo-Json)

Write-Host "Human Verified Relationship: $($verifiedRel.epistemic_state) (Verified By: $($verifiedRel.verified_by))"
```
