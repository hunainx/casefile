# Epic E4 Demo Walkthrough — Knowledge Core (Assertions, Epistemics & Provenance)

This document provides a complete, verifiable step-by-step walkthrough of the **Casefile Knowledge Core**, covering the Assertion Spine (PRD §6, §12), the 7-state Epistemic Ladder (PRD §6.5, §13), Invariants I1, I2, I3 (PRD §6.3–§6.6), Provenance Derivation chains (PRD §14, §19), and Divergence Detection.

---

## 1. Overview of Demonstrated Capabilities

1. **The Single Assertion Spine (PRD §6.4)**: All intelligence primitives (attributes, relationships, events, claims) share a unified `Assertion` schema with strict provenance.
2. **Invariant I1 (AC-EPI-02 / Grounding Requirement)**: Non-human asserters (`model`, `deterministic`) MUST supply at least one resolvable evidence locator. Empty grounding is rejected with `HTTP 422 grounding-required`.
3. **Invariant I2 (AC-EPI-01 / Epistemic Authority)**: AI/machine asserters can NEVER assert `Verified` or `Refuted`. Attempts are rejected by database CHECK constraints and Assertion Service middleware, emitting a `PolicyViolationAttempted` security audit event.
4. **The 7-State Epistemic Ladder (PRD §6.5 / AC-EPI-05)**: Strictly enforced single vocabulary (`Unknown`, `Possible`, `Likely`, `Supported`, `Verified`, `Contradicted`, `Refuted`).
5. **Human Promotion & Validation (PRD §6.5)**: Investigators validate candidate machine assertions with explicit rationale, transitioning `plane: machine → record`.
6. **Invariant I3 & Divergence Tracking (PRD §6.3 / AC-EPI-03, AC-EPI-04)**: When pipeline recomputation produces a conflicting candidate, the human-verified record is preserved unchanged, raising a `DivergenceNotice` and `ContradictionAlert`.
7. **Lineage & Supersession**: Full audit trail of assertion revisions via `POST /assertions/:id/supersede`.

## 3. Step-by-Step Walkthrough

### Step 1: Register Organization & Create Investigation

```powershell
# 1. Register investigator account
$reg = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/auth/register" -ContentType "application/json" -Body (@{
    email = "lead-investigator@acme-corp.example"
    password = "MasterPassword123!"
    name = "Elena Rostova"
    orgName = "Acme Intelligence Group"
} | ConvertTo-Json)

$TOKEN = $reg.accessToken
$TENANT_ID = $reg.user.tenantId
$HEADERS = @{
    "Authorization" = "Bearer $TOKEN"
    "Content-Type" = "application/json"
}

# 2. Create Workspace
$ws = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/workspaces" -Headers $HEADERS -Body (@{
    name = "Financial Crimes & Forensics"
} | ConvertTo-Json)
$WORKSPACE_ID = $ws.id

# 3. Create Investigation
$inv = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations" -Headers $HEADERS -Body (@{
    workspace_id = $WORKSPACE_ID
    name = "Operation Horizon"
    objective = "Trace offshore beneficial ownership and undisclosed transactions"
} | ConvertTo-Json)
$INV_ID = $inv.id

Write-Host "Created Investigation $INV_ID in Workspace $WORKSPACE_ID"
```

### Step 2: Invariant I1 Demonstration — Grounding Required for Machine Asserters

Attempt to submit a candidate extraction without evidence grounding:

```powershell
# Attempt AI assertion with empty evidence_ids
try {
    $res = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/assertions" -Headers $HEADERS -Body (@{
        kind = "relationship"
        subject_type = "entity"
        subject_id = [guid]::NewGuid().ToString()
        predicate = "controls_shell_company"
        object_type = "entity"
        object_id = [guid]::NewGuid().ToString()
        asserter = @{ type = "model" }
        epistemic_state = "Supported"
        evidence_ids = @()  # Empty grounding!
    } | ConvertTo-Json)
} catch {
    Write-Host "Invariant I1 Enforcement Success (HTTP 422):" $_.Exception.Response.StatusCode
}
```

### Step 3: Invariant I2 Demonstration — AI Cannot Verify

Attempt an AI write that claims `Verified`:

```powershell
$evidenceId = [guid]::NewGuid().ToString()

try {
    $res = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/assertions" -Headers $HEADERS -Body (@{
        kind = "claim"
        subject_type = "entity"
        subject_id = [guid]::NewGuid().ToString()
        predicate = "beneficial_owner"
        object_type = "entity"
        object_id = [guid]::NewGuid().ToString()
        asserter = @{ type = "model" }
        epistemic_state = "Verified"  # Forbidden for model asserters!
        evidence_ids = @($evidenceId)
    } | ConvertTo-Json)
} catch {
    Write-Host "Invariant I2 Enforcement Success (HTTP 422):" $_.Exception.Response.StatusCode
    Write-Host "Security event 'PolicyViolationAttempted' emitted to immutable audit log."
}
```

### Step 4: Create Grounded Machine Assertion (Candidate)

```powershell
$subjectEntityId = [guid]::NewGuid().ToString()
$verifiedTargetId = [guid]::NewGuid().ToString()

$assertion = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/assertions" -Headers $HEADERS -Body (@{
    kind = "relationship"
    subject_type = "entity"
    subject_id = $subjectEntityId
    predicate = "director_of"
    object_type = "entity"
    object_id = $verifiedTargetId
    asserter = @{ type = "model" }
    epistemic_state = "Supported"
    confidence = 0.88
    evidence_ids = @($evidenceId)
    derivation = @{
        parents = @()
        transform = "llm_corporate_registry_extractor"
        transform_version = "2.1.0"
        executed_at = (Get-Date).ToUniversalTime().ToString("o")
    }
} | ConvertTo-Json)

$ASSERTION_ID = $assertion.id
Write-Host "Created Machine Assertion $ASSERTION_ID on plane: $($assertion.plane) (Epistemic State: $($assertion.epistemic_state))"
```

### Step 5: Human Validation & Record Plane Promotion

The investigator reviews the primary evidence and validates the assertion:

```powershell
$validated = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/assertions/$ASSERTION_ID/validate" -Headers $HEADERS -Body (@{
    epistemic_state = "Verified"
    rationale = "Examined original stamped corporate registry certificate from Companies House (Scan Ref #8849)."
} | ConvertTo-Json)

Write-Host "Assertion Promoted to Record Plane:"
Write-Host "  Epistemic State: $($validated.epistemic_state)"
Write-Host "  Plane: $($validated.plane)"
Write-Host "  Reviewed By: $($validated.reviewed_by)"
Write-Host "  Rationale: $($validated.review_rationale)"
```

### Step 6: Invariant I3 & Recomputation Divergence

A newly deployed extractor reprocesses the corpus and proposes a conflicting director:

```powershell
$conflictingTargetId = [guid]::NewGuid().ToString()

$recomputed = Invoke-RestMethod -Method Post -Uri "$API_URL/v1/investigations/$INV_ID/assertions" -Headers $HEADERS -Body (@{
    kind = "relationship"
    subject_type = "entity"
    subject_id = $subjectEntityId
    predicate = "director_of"
    object_type = "entity"
    object_id = $conflictingTargetId  # Conflicting entity ID!
    asserter = @{ type = "model" }
    epistemic_state = "Supported"
    evidence_ids = @([guid]::NewGuid().ToString())
    derivation = @{
        parents = @($ASSERTION_ID)
        transform = "v3_experimental_extractor"
        transform_version = "3.0.0"
    }
} | ConvertTo-Json)

Write-Host "Recomputation Results (Invariant I3):"
Write-Host "  Divergence Notice Status: $($recomputed.divergence_notice.status)"
Write-Host "  Notice Type: $($recomputed.divergence_notice.divergence_type)"

# Verify verified assertion is UNTOUCHED
$check = Invoke-RestMethod -Method Get -Uri "$API_URL/v1/investigations/$INV_ID/assertions/$ASSERTION_ID" -Headers $HEADERS
Write-Host "  Verified Record Status: $($check.epistemic_state) (Target: $($check.object_id))"
```
